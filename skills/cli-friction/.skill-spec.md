# skill-spec: cli-friction

- **name**: cli-friction
- **description**: Do a task the user gives with a CLI, learning it only from its help, output and errors (never its source or repo files), and log every point where the help fell short; end with a friction report and ticket drafts that would fix the help.
- **should_fire**:
  - 测一下 afkconvoy 的 help 够不够用：不看源码，只靠 --help 查出 ~/Developments/agent-cli 这个 checkout 的 fleet 用哪个 label 认定 issue 可以开工，看看 help 哪里不够。
  - 只看 help 用 hkj 把 ~/Movies/talk.mp4 转成字幕，把过程中 help 缺的信息记下来，我要改进这个工具。
  - Use diskreap from its --help alone to find what is eating space in ~/Library/Caches, and tell me where the help made you stumble.
  - dogfood 一下 wxread 的帮助：别读它的代码，只用 help 把我书架上最近读的三本书列出来，找出摩擦点。
  - Agent 用 underdraw 老出错。你别看项目文件，只用它的 help 把 ./sketch.svg 转成 PNG，记下 help 让你卡住的地方。
- **decoys**:
  - 给 afkconvoy 加一个 status 子命令。（agent-cli：造/改 CLI）
  - 帮我改一下 afkconvoy plan 的 --help 文案，把 frontier 讲清楚。（直接改 help，不是试用）
  - afkconvoy doctor 报错了，帮我看看怎么回事。（排障）
  - 用 afkconvoy plan 看看 fleet 现在在干嘛。（单纯使用 CLI）
  - 测测我对 Rust 所有权的理解。（test-me）
  - afkconvoy 的测试套件太慢了，看看时间花在哪。（test-speed-review）
- **examples**:
  - `/cli-friction afkconvoy：在 ~/Developments/agent-cli 里查出 fleet 认定 issue 可以开工看的是哪个 label`
  - 「只用 help，让 inspectvideo 总结这个视频 <url>，看 help 缺什么」
- **needs**: the CLI on PATH; `gh` only for filing tickets after the user confirms. No scripts.
- **functional_test**: run the skill on the first example, with afkconvoy behind a PATH shim that passes only help and the commands that write nothing (`config`, `check`, `doctor`, `show`; not `plan`, which may push a probe to the remote). Pass when all hold:
  1. the answer names the label the fleet uses, consistent with `afkconvoy config` run in that checkout;
  2. no tool call reads or searches files under `~/Developments/afkconvoy` or the checkout's own files (Read/Grep/Glob, or `cat`/`rg`/`sed`/`head` in Bash);
  3. the report has at least one friction entry with every field (needed, looked, did, evidence, fix, cost) filled;
  4. nothing is filed (no `gh issue create`).
- **target**: dedicated repo `sunfmin/cli-friction`
- **visibility**: public
- **decided with Felix**: tasks come from the user each run, the agent designs none; the constraint is in the instructions, no hard sandbox (a headless sealed tester was prototyped and dropped); output is a friction report plus ticket drafts, filed only after confirmation.
